### 2.3 도메인 경계 설계 (특장점으로 쓸 만한 대목)

```
vision (호스트, ROS 없음, Py3.12, cv2 있음)
   │  localhost TCP 8091  +  JSON Lines (schema_version=1)
   ▼
shim_node (컨테이너, Py3.10, rclpy 있음, cv2 없음)
   │  ROS2 토픽
   ▼
fc_ros OffboardNode
```

- **코드 교차 import 0건 / colcon·pip 빌드 의존 0건.** 한쪽을 통째로 교체해도 상대는 재빌드가 필요 없다.
- 이 구조를 택한 결정적 이유는 실측이다 — RPi 호스트는 Ubuntu 24.04(ROS2 Jazzy 계열)인데
  FC 컨테이너는 Humble이고, **Humble↔Jazzy는 교차통신을 지원하지 않는다.** 같은 ROS2 그래프에
  올릴 수 없다는 물리적 제약을 소켓 경계로 흡수했다. ✅
- 부수 효과: **vision이 죽어도 FC는 살고, FC가 죽어도 vision은 계속 좌표를 뱉는다.**

### 4.1 FC — `fc_bridge` (ROS2 비의존 순수 Python 라이브러리)

- `planning/speed_profile.py` — **곡률 기반 속도 프로파일** 생성 + 종단 감속(`apply_terminal_decel`)
- `guidance/l1_guidance.py` — L1 유도 (lookahead 20m)

### 4.2 FC — `fc_ros` (ROS2 노드)

3개 노드: `TelemetryNode`(상태 구독) / `OffboardNode`(비행 상태머신) / `MissionNode`(미션 업로드).

**OffboardNode 상태머신 — 12개 상태:**
```
ARM_TAKEOFF → CLIMBING → TRANSITION_FW → STREAMING → [ENTRY] → FOLLOWING
            → TRANSITION_MC → HOLD → LANDING → DONE
                  + OVERRIDE (어느 상태에서든 진입)
                  + PILOT_TAKEOVER (조종사 인계 감지 시 노드 정지)
```
- `vehicle_type` 런타임 파라미터로 **MC 전용 기체는 천이 2단계를 생략**해 동일 코드로 두 기체 운용
- `waypoint_frame` 파라미터로 경로 기준계를 **이륙지점 기준 / EKF 로컬 절대** 선택 (2026-07-25 사고 대응으로 신설)
- **안전 장치 다층화** ✅:
  - 상태별 탈출 타임아웃 4종 (`climbing_timeout` 120s / `transition_fw_timeout` 90s / `transition_mc_timeout` 30s / `entry_timeout` 60s)
  - **이륙지점 기준 수평거리 상한 300m** — 상태머신이 어디서 막히든 작동하는 마지막 기하학적 제동장치
  - RC 모드스위치 + ROS 토픽 이중 오버라이드 → 실패 시 AUTO.LOITER 폴백
  - MC 웨이포인트 **정착 판정**(반경 진입 + 속도 임계 + 유지시간) — 코너 절삭 방지

### 4.3 Vision — 검출·측위 파이프라인

**아키텍처 한 줄 요약: Config-driven callable pipeline.**
모든 처리 단계가 `VisionState → VisionState` 함수이고, 파이프라인은 모듈 내부를 모른 채
**순서와 파라미터만** 안다. → 새 검출기 추가 = 클래스 1개 + registry 1줄 + yaml 프리셋.

- **검출 모듈 14종**: ColorFilter / Illumination / Denoise / Edge / Morphology / RectDetector /
  BackgroundSubtractor / KalmanTracker / TemporalFusion / WhiteFieldDetector / BlackVMatcher /
  RedRingDetector / WhiteBoxDetector / DistressMatGeometry / ArucoDetector
- **시나리오 프리셋 7종**: `vertiport_coarse` / `vertiport_fine` / `distress_coarse` /
  `distress_fine` / `low_light` / `single_frame` / `video`
- **핵심 계약 파일 (`core/`)**:
  | 파일 | 역할 |
  |---|---|
  | `state.py` | `VisionState` / `Detection` 데이터 계약 |
  | `target.py` | `TargetEstimate` + `solve_target_pose()` (solvePnP → 상대 pose) |
  | `state_machine.py` | 타겟 종류 무관 **공통 착륙 상태머신** 7상태 |
  | `frames.py` | 카메라 광학 → body FLU → body FRD 좌표 체인 |
  | `wire.py` | JSON Lines 와이어 포맷 + 페일세이프 계약 (`SCHEMA_VERSION=1`) |

- **착륙 상태머신 7상태**: `ACQUIRE → CENTER_DESCEND → LOCK → PRECISION_SERVO → TERMINAL`
  (+ `HOLD` / `ABORT_ASCEND`)
  - **커밋 게이트가 구조적으로 강제됨** — `PRECISION_SERVO`/`TERMINAL`은 오직 `LOCK`의 연속 확정
    프레임 조건을 통과해야만 도달 가능하고, 코드상 다른 진입 경로가 **없다**. 후보가 모호하면 `HOLD`로 거절.
  - **순수 로직** — 파일 I/O·wall-clock·난수를 쓰지 않아 같은 관측열은 항상 같은 상태열을 낸다(결정론).

- **관측성 스택 (3경로)** ✅:
  1. `utils/blackbox.py` — 프레임별 JSONL 블랙박스 + **거절 이유까지 로깅** (비차단 drop-oldest 큐)
  2. `utils/stream.py` — MJPEG-over-HTTP 라이브 스트림(검출 오버레이 포함), 실측 **17fps**
  3. `tools/h264_stream.py` — H.264 저지연 원본 스트림, 실측 **30fps / 지연 25~41ms**
  4. `replay.py` — 녹화 폴더/영상 **결정론적 재생** (같은 입력 → 같은 출력, 회귀 assert 가능)
  5. `tools/jsonl_view.py` — JSONL → score/latency/state 3단 시계열 플롯 PNG

- **현장 대응 도구**:
  - `tools/color_calibrate.py` — **현장 색 캘리브레이터**. ROI의 HSV 백분위수(p5~p95)에서
    검출 임계값을 자동 제안. 빨강 Hue 랩어라운드 자동 판정. → **대회 직전 색 규정이 바뀌어도 코드 수정 0**
  - `tools/calib_capture.py` / `calib_analyze.py` — 체커보드 캘리브레이션 파이프라인 (현재 동결)

### 4.4 시뮬레이터 — `vtol_sim`

알고리즘 후보를 실기체 없이 비교 평가하기 위한 자체 구축 시뮬레이터.

- **동역학**: point-mass 3DOF + MC/FW 모드 매니저
- **교란 모델**: 돌풍/바람 모델, GPS 잡음, 액추에이터 잡음, 통신 지연
- **경로계획기 10종 이상**: eta³ clothoid (v3.1/v3.2/stage2), D-iterpin, iterpin, Dubins,
  piecewise clothoid, B-spline(2종), Hermite B-spline, Quintic Hermite B-spline, spline, straight-line
- **추종제어기**: NLGL, MPC, inner-loop

## 8. 특장점 — 셀링 포인트 (근거 포함)

> 보고서 "우리 시스템의 특장점" 절의 재료. 각 항목에 **근거 파일**을 붙여 놨다.

### 8.1 3단 검증 피라미드 — "검증 없이는 기체에 올라가지 않는다"

```
 [3층] 실기체 비행       59회분 로그 + ulog 79건 자동 분석 (analyze_flight.py)
   ↑ 통과해야 올라감
 [2층] SITL 회귀 캠페인   24런 자동 실행·자동 판정 (run_scenario.py / analyze_run.py)
   ↑ 통과해야 올라감
 [1층] 단위 테스트       1,285건, ROS2 없이 27초에 전량 실행
```
비행 로직을 rclpy 비의존 순수함수로 뽑아냈기 때문에 1층이 가능하다. **구조가 검증을 가능하게 한
사례**로 설명할 수 있다.

### 8.2 변경 내성 — "대회 규정이 직전에 바뀌어도 코드를 안 고친다"

- **Config-driven 파이프라인**: 검출 순서와 파라미터가 전부 yaml. 코드 수정 없이 파이프라인 교체
- **현장 색 캘리브레이터**: 현장에서 ROI 한 번 찍으면 HSV 임계값을 자동 산출
- **레이어드 설정**: 기본값 → 카메라 프로파일 → 타겟 프로파일 → 런타임 오버라이드(launch 인자/CLI)
- **매직넘버 금지 규율**: 임계값을 코드에 박지 않고 전부 파라미터화 (저장소 전역 규칙)
- 실증: ③ 하기구역은 **대회측이 규격을 비공개**했는데, 이 구조 덕에 "획득 후 캘리브레이터로 흡수"라는
  계획이 성립한다

### 8.3 관측성 — "현장에서 실패해도 원인을 안다"

- **JSONL 블랙박스**가 프레임별 검출 결과 + **거절 이유**까지 기록 (왜 안 잡혔는지가 남는다)
- **결정론적 재생(replay)** — 녹화한 비행을 노트북에서 그대로 재현. 같은 입력이면 항상 같은 출력
- **provenance 헤더** — 모든 로그에 config + git 해시 + 캘리브레이션 ID가 자동으로 박힌다
- **3경로 라이브 피드백** (H.264 원본 / MJPEG 오버레이 / JSONL 플롯)
- 비행 로그 쪽도 동일 — `analyze_flight.py`가 폴더 하나로 표준 진단서를 자동 생성

### 8.4 페일세이프 설계 — "침묵 / 무효 / 사망"의 3분법

대부분의 시스템이 뭉개는 구분을 **와이어 포맷 수준에 형식으로 박았다**:

| 상황 | pose 토픽 | status 토픽 |
|---|---|---|
| 정상 검출 | 발행 | `OK` |
| **안 보임** | 침묵 | **`WARN` + 사유** |
| **생산자 사망** | 침묵 | **`ERROR` + `producer_eof`** |
| shim 사망 | 침묵 | 침묵 |

- "0을 채워 계속 발행"하는 안은 **명시적으로 기각**했다 — 0은 가장 위험한 거짓말이기 때문
- 상태머신의 `command`는 `command_hint` + `command_is_advisory:true` + 타입명 `state_hint`
  **세 겹으로** "명령이 아님"을 형식에 박아, vision이 FC를 조종할 수 없게 했다
- 좌표 필드는 **프레임 이름을 필드명에 박는다**(`position_cam`/`position_flu`/`position_frd`)

### 8.5 정직한 불확실성 전파 — "모르는 것을 모른다고 말하는 구조"

- 카메라 캘리브레이션이 미실측이므로 `accuracy: unverified` / `not_for_closed_loop_30cm: true`
  플래그를 아티팩트에 박았고, 이 플래그가 **로그 → 와이어 레코드 → ROS 토픽 KeyValue까지
  자동으로 따라간다.** 소비자가 정밀도를 과신할 수 없다.
- 마운트 요각 ψ_m이 미측정이라 값을 지어내지 않고 `MOUNT_YAW_PSI_M_MEASURED=False`
  플래그를 함께 실어 보낸다.
- 공분산을 모를 때 0(=완벽히 정확)이 아니라 `1e6`(=모름)을 넣는다.
- 초록 매트가 0.105m 뜬 구조물이라 라이다 AGL과 어긋나는데, **모르는 기하를 가정해 보정하지 않고**
  `plane_reference` / `platform_height_m` / 차이값을 그대로 수출해 FC가 판단하게 한다.

### 8.6 결정론 우선 — ML을 쓰지 않은 이유가 있다

고전 CV(OpenCV)만 사용. 근거:
- **결정론 = 신뢰도** — 대회 당일 오작동·오인식을 절대 피해야 한다는 요구 #1
- **RPi5 경량** — 온보드 실시간 처리
- **데이터셋 부담 0** — 타겟이 전부 피듀셜/고대비 색·형상이라 학습이 불필요
- 부수 효과: 재생(replay)이 비트 단위로 재현 가능해 회귀 테스트가 성립

### 8.7 상류 오픈소스까지 파고드는 문제 해결력

- 6.5 km 경로 폭주의 원인이 **우리 코드가 아니라 PX4 상류 회귀**임을 소스 라인·커밋 계보로 확정
- 원인 커밋(가드 도입 → revert)을 특정하고, revert 사유("navigator가 보장한다")가 오프보드
  경로에는 적용되지 않는다는 것까지 규명
- **2줄 패치 + 빌드 + SITL 회귀 검증**까지 완주, 회귀 0건
- 부수적으로 "펌웨어가 패치 여부를 자기신고하지 않는다"(버전 문자열이 순정과 동일)는 함정을
  발견해 **sha256 대조**를 배포 절차에 넣음

### 8.8 도메인 격리 — 3인 병렬 개발이 가능한 구조

- 도메인별 독립 진입점 문서 + 독립 트랙 보드 + 커밋 태그(`[main]`/`[mc-hw]`/`[sitl]`/`[vtol-hw]`/`[vision]`)
- vision과 FC는 **서로의 문서를 읽지 않는다**(의도적 컨텍스트 격리)
- 실제로 2026-07-28 하루에 vision 3트랙 + FC 1트랙이 **같은 브랜치에서 병렬 진행**되고 충돌 0건

## 9. 미래 구조 — 로드맵

### 9.1 단기 (2차예선 직전까지)

| # | 항목 | 도메인 | 상태 |
|---|---|---|---|
| 1 | **착륙점 기하 재설계** — 기체 반경 기반 안전창에서 착륙점 도출 (매트 이탈 경로 차단) | vision | ✅ 완료 (`bfd6cca`) |
| 2 | **shim setpoint 변환** — 기체 자세 구독 → 절대 목표점 산출(`/vision/landing_setpoint`) | vision | ✅ 완료 + **실기체 종단간 실증** (`27dffa3`/`8ec3c84`) |
| 3 | **사전정보 기반 후보 스코어링** — 기지 크기 + AGL + 자세로 예상 형상 예측 → 후보 랭킹 | vision | ✅ 완료 (`bbd1413`) |
| 4 | **비행 기조 전환** — "실패 시 재상승" 폐기 → 기하 예산 안에서 "밀어붙이기" | vision | ✅ 완료 (`256dd42`) |
| 5 | **OffboardNode 정밀착륙 서브상태** — 폐루프를 닫는 마지막 한 칸 | FC | 🔵 미착수 |
| 6 | PX4 패치 실기체 플래시 + 비-정북 레그 실비행 | FC | 🔵 승인 대기 |
| 7 | R5(경로·고도 품질) / R6(선회 품질·플래너 비동기화) | FC | 🔵 계획 |

> **2026-07-28 갱신:** 1~4번이 이 문서 작성 중 전부 완료·푸시됐다(vision 테스트 886 → **1,028**).
> 즉 **정밀착륙 폐루프에서 vision 도메인이 담당하는 몫은 전부 끝났고, 남은 것은 FC 도메인의
> 소비 서브상태 하나**다. 보고서에서 "vision 파트 완료, FC 연결만 남음"으로 서술 가능하다.

### 9.2 중기 (2차예선 이후)

- **실측 카메라 캘리브레이션 재개** (체커보드 85장) → **폐루프 30cm 정밀착륙 검증**
- **골든셋 실촬영 교체** — 현재 전량 합성 데이터인 회귀 픽스처를 실제 자갈/조명/그림자로 교체
- **CC(명령 제어) 도메인 신설** — 타겟 지정·시작 트리거 인터페이스
- **LANDING_TARGET 네이티브 precision-land 피벗** — 자체 서보가 정밀도 미달 시 대안 경로
  (와이어 포맷을 상대 pose로 둔 덕에 **양쪽 다 지원 가능**하게 이미 설계돼 있음)

### 9.3 장기 / 확장 포텐셜 (보고서 "포부" 절 재료)

- **소형 단일물체 창의적 탐색 설계** — 넓은 구역에서 소형 목표물을 능동 탐색하는 임무 확장
- **글로벌셔터 컬러 카메라 폴백 경로** — 롤링셔터 한계가 드러나면 OG02B10/OV9782/IMX296로 교체
  (FrameSource 어댑터 뒤에 격리돼 있어 **코어 코드 변경 0**)
- **인코딩 오프로드 어댑터** — Pi5 SW 인코딩이 병목이면 Pi4 오프로드 또는 별도 에어유닛으로 스왑
  (EncoderSink 어댑터로 이미 대응)
- **불확실성 정량화** — `PoseWithCovarianceStamped`의 6×6 공분산 자리가 **이미 비어 있는 채로
  예약**돼 있어, 실측 캘리브레이션 후 값만 채우면 기성 필터(`robot_localization` 등)와 바로 결합

> 📌 **"포텐셜" 서술의 핵심 논거:** 이 시스템의 확장성은 희망이 아니라 **어댑터 경계로 코드에
> 이미 박혀 있다.** 카메라·인코더·통신 transport·측위 방식(자체 서보 vs 네이티브) 네 축이 전부
> 인터페이스 뒤에 격리돼 있어, 교체 시 코어가 바뀌지 않는다.

| **PX4 상류 버그 의존** | 실기체 PX4를 특정 리비전에 핀 고정 중 | "실기체 펌웨어 리비전을 특정하고 패치를 자체 관리한다"— 통제력으로 서술 |
