## 2. 슬라이드별 골격

### S01 — 참가팀 현황
- 팀명 **수리독수리** / 연세대학교 / 지도교수 **유정훈**(기계공학부)
- 팀원표: 양식 PDF 표 그대로 (직위·성명·주민번호 앞7자리·학년·소속·학과·E-mail·담당역할)
  - 1차 기준: 팀장 **김승원**(2학년, 기계공학부) / **김태훈**(2학년, 물리학과)
- 🔴 **[빈칸] 팀원 변경/추가 여부 확정 필요** — "팀원 변경은 2차 제출 이후 불가"
- 자료: 1차 보고서 5장 그대로 재활용

### S02 — 추진체계
- 양식의 예시 조직도(시스템통합/기체설계/임무제어/지상통제/조종사)를 **2인 팀 현실에 맞게 축약**
- 제안: 기체설계·시스템통합(팀장) / 임무제어·지상통제(SW) / 조종사 [빈칸]
- 🔴 **[빈칸] 조종사 누구인지** — 안전 항목이라 비워두면 눈에 띈다

### S03 — 전체 시스템 구성도
- 한 장짜리 블록도: 기체 ← FC(Pixhawk 6C) ← CC(RPi5) ← 카메라/라이다, 지상국(GCS/FPV)
- "하드웨어·소프트웨어 **전부 자체 제작**" 한 줄 (1차부터 이어지는 우리 메시지)
- 1차 대비 **뭐가 달라졌는지**를 이 장에서 한 번에 보여주면 좋음 (계획서 → 구현체)
- 자료: `docs/qualifier2_report_inventory.md` §2.1 아키텍처 다이어그램

### S04 — 기체(수리1호) 개발 현황
- 🔴 **[전적으로 팀장 담당]** — 저장소에 기체 HW 데이터가 거의 없다
- 들어갈 것: 완성 사진 / 제원표(익폭·중량·전장) / 1차 설계 대비 변경점 / 제작 방식
- 1차에서 재활용 가능: ASA AERO+카본파이프 3D프린팅, elliptical wing+NACA2412, V-tail,
  Tarot 4114 320kv + 1545 prop(쿼드), 푸셔, 설계하중(80km/h, AoA 15°, 쿼드 12kgf·푸셔 4kgf)
- 🔴 **[빈칸] MTOW·익폭·전장·배터리 실측치**

### S05 — 온보드 컴퓨팅·소프트웨어 스택 현황
- 하드웨어: Pixhawk 6C(PX4 v1.18) / RPi5 8GB+NVMe / Dual Holybro M10 GPS / 카메라 IMX708 / 1D 라이다
- 소프트웨어: 3도메인(비행제어·객체인식·시뮬레이터) **약 51,400줄 / 205 파일**
- "도메인 간 코드·빌드 의존 0, 표준 인터페이스로만 결합" — 교체 가능성 강조
- 자료: inventory §3, §4

### S06 — 미완성 부분 개발/시험 계획
- 정직하게 3~4개만: ①정밀착륙 폐루프 FC측 연결 ②VTOL 실기체 고정익 자율비행 실증
  ③카메라 정밀 캘리브레이션 ④구조장치 통합
- 각각 **언제·어떻게** 한 줄씩 (계획이 있다는 게 핵심, 없는 걸 감추는 게 아니라)
- 🔴 프레이밍 주의 → inventory §11 표 참고

### S07 — 안전장치 구현 상황
- **다층 안전장치**로 묶어서 제시:
  1. RC 모드스위치 + ROS 토픽 이중 오버라이드 → 실패 시 AUTO.LOITER 폴백
  2. 조종사 인계 감지 시 자동노드 정지(PILOT_TAKEOVER) — 실비행 사고 대응으로 신설
  3. 상태별 탈출 타임아웃 4종 + **이륙지점 기준 거리상한 300m**
  4. 에너지 기반 동적 페일세이프(1차 설계) / 비상 천이 제어(1차 설계) — 구현 상태 [빈칸]
- 각 장치에 "SITL/실비행에서 실제로 발동한 사례" 붙이면 설득력 큼
- 자료: inventory §4.2, 1차 보고서 4장

### S08 — 자동비행 아키텍처
- 3계층: **경로생성 → 경로추종 → 자세제어**, 계층마다 알고리즘 교체 가능
- 1차의 "완전한 모듈화 + 자율적 알고리즘 대체" 주장이 **실제 코드 구조로 실현됐음**을 보여주는 장
- ROS2 노드 3종(Telemetry/Offboard/Mission) + rclpy 비의존 순수 라이브러리 분리 구조

### S09 — 경로생성
- eta³ clothoid — 곡률 연속, 자체 최적화(NR 잔차 분산, 가상 WP 삽입)
- **자체 시뮬레이터에서 경로계획기 10종 이상 비교해 선정**했다는 점 강조
- 그림: `python fc_bridge/run_phase1.py --dry-run --plot --save-plot results/path.png` (6패널)

### S10 — 경로추종 + 비행 상태머신
- L1 유도 / 위치 setpoint 채널(고정익 오프보드는 속도 setpoint 무시 — 실측으로 확정)
- 상태머신 12상태 전이도 (ARM→CLIMBING→TRANSITION_FW→…→LANDING)
- 자료: `docs/flight_plan.md` "목표 비행 시퀀스" 텍스트 다이어그램 → 도식화

### S11 — 항법·상태추정 / 파라미터 실측 근거
- "값을 감으로 안 정했다"는 장. 예: `v_cruise=18.0` = 실측 `FW_AIRSPD_TRIM` 15 + 배풍마진 3
- 경로생성 비용/품질이 **16↔17에서 계단**으로 갈린다는 실측표 (inventory §7.4)
- 이런 장이 하나 있으면 질의응답에서 강함

### S12 — 검증 체계 (3단 검증 피라미드) ★
```
 [3층] 실기체 비행     59회분 로그 + ulog 79건 자동 분석
 [2층] SITL 회귀       시나리오 24런 자동 실행·자동 판정
 [1층] 단위 테스트     1,811건 (FC 783 + Vision 1,028), ROS2 없이 실행
```
- 핵심 메시지: **"검증을 통과하지 못한 코드는 기체에 올라가지 않는다"**
- 구조적 근거: 비행 로직을 ROS 비의존 순수함수로 뽑았기 때문에 1층이 가능
- 이게 대부분 팀이 못 하는 이야기 → **여기에 슬라이드 1장 온전히 쓸 값어치 있음**

### S13 — SITL 시험 결과
- SITL-1~4 전 항목 PASS → SITL-7 전면 회귀 캠페인 24런
- 사례 1건 깊게: **PX4 상류 회귀 버그를 소스 계보까지 추적해 2줄 패치로 해소**
  - 북향이탈 21.78 → **0.38 m** / 고도편차 판정 FAIL → **PASS** / 회귀 0건
- 그림: `logs/2026-07-27_sitl_vtol_campaign/*/verdict.md`, 궤적 플롯

### S14 — 실비행 시험 결과 + 향후 계획
- 실비행 **59회분** 누적, 매 비행 로그 전량 회수·자동 분석 → 결함 규명 → 수정 → 재배포 사이클
- 🔴 개별 사고 나열 금지. **집계와 사이클**로 서술 (inventory §11)
- 성과 사례: 조종사 개입 0으로 완주한 비행(경로이탈 최대 0.94m, WP 최근접 0.10~0.64m)
- 향후 시험 계획 3~4줄 (VTOL 전 사이클 / 정밀착륙 / 통합 리허설)

### S15 — 임무수행 시나리오
- 임무 전체 흐름 한 장: 이륙 → 천이 → 경로비행 → 목표구역 도착 → 역천이 → 스캔 →
  타겟 포착·확인 → 정중앙 상공 정렬 → 정밀착륙 → (구조) → 복귀
- 타겟 4종(버티포트 / 조난자 구역 / 하기구역 / 단순착륙)과 각각의 착륙지점 규격
- 자료: inventory §5 표

### S16 — 객체인식
- **고전 CV(OpenCV) 채택 근거**: 결정론=신뢰도, RPi5 경량, 데이터셋 0
- coarse→fine 2단 검출 + **GSD 표로 "왜 2단 하강이 물리적으로 강제되는가"**
- 검출 모듈 14종 / 프리셋 7종 / config만 바꿔 파이프라인 교체
- 실측: 프레임당 18ms, solvePnP 거리오차 0.25~0.58%
- 그림: 검출 오버레이 (`vision/results/sink_overlay_demo/`)

### S17 — 정밀착륙 (상대 pose 폐루프)
- GPS 절대좌표는 1~2m가 한계 → **30cm는 카메라가 오차를 직접 재는 폐루프로만**
- vision → shim → FC 데이터 흐름 한 장 + 페일세이프 3분법(침묵/무효/사망)
- 현재 상태: vision 담당분 완료 + 실기체 종단간 실증, FC 소비부가 다음 단계
- 착륙점을 **기체 최외곽 반경 기반 안전창**에서 산출 (물리 치수 반영)

### S18 — 구조 장치(아기수리)
- 🔴 **[전적으로 팀장 담당]** — 저장소에 자료 없음

- 필요: 제작 사진 / 동작 시험 영상 / 1차 대비 변경점

### S19 — 보완 계획 / 남은 일정

- S06(미완성)과 짝을 이루게 — 같은 항목이 여기서 일정으로 바뀜

### S20 — 비행시험 데이터 & 영상 / 마무리

> 같은 그림을 써도 **캡션을 "설계안"에서 "구현 결과"로 바꿔야** 한다. 1차 문장을 그대로
> 복사하면 계획서처럼 읽혀서 손해다.
