- **직전 완료(2026-07-22b, RPi 실카메라 하드웨어 세션 — RPi/실카메라 작업 금지가 이 세션부터 해제됨):** 카메라 브링업 4개 선택지 중 **V4L2 RAW 직접 캡처 + 수동 디베이어**로 확정 진행, **실카메라로 실제 촬영 검증까지 완료**. 상세:
  - **libcamera 우회, rp1-cfe 미디어 파이프라인 직접 구성으로 브링업 성공.** 커널/V4L2 자체는 이미 정상이었지만(6세션 전 확인), `/dev/video0`(rp1-cfe-csi2_ch0)가 "MC-centric" 캡처 노드라 `v4l2-ctl --set-fmt-video`만으로는 `VIDIOC_STREAMON`이 `-EPIPE`(Broken pipe)로 실패했다. `dmesg` dynamic_debug(`module rp1_cfe +p`, `file v4l2-subdev.c +p`)로 실제 커널 로그를 라인 단위로 추적해 3개 원인을 순서대로 확정·해결:
    1. `"csi2":4 -> "rp1-cfe-csi2_ch0":0` 링크가 기본 비활성("csi2_ch0 node link is not enabled.") → `media-ctl -l`로 활성화.
    2. csi2 싱크 패드0 `field:any` vs 센서 소스 패드 `field:none` 불일치("field does not match") → `media-ctl -V`로 명시적 `field:none` 통일.
    3. 임베디드 메타데이터 패드(imx708 패드1, IMMUTABLE 링크라 항상 파이프라인에 포함)의 실제 폭 28800 vs csi2 싱크 패드1 기본값 16384 불일치("width does not match") → 실제값 readback 후 `v4l2-ctl --set-subdev-fmt`로 명시적 지정.
    부가로 센서(imx708)가 임의 해상도를 가장 가까운 지원 모드로 스냅한다는 것도 실측 확인(640x480 요청 → 1536x864로 스냅) — 그래서 파이프라인 구성 함수가 항상 readback한 실제값을 하위 단계에 전파하도록 구현.
  - **`vision/tools/rpi_capture.py` 전면 재작성:** 기존 GStreamer `libcamerasrc` 버전(이 RPi에서 작동 불가였음) 폐기, 위 media-ctl/v4l2-ctl 파이프라인 구성 + `unpack_raw10()`(MIPI RAW10 4픽셀/5바이트 언패킹) + `debayer_to_bgr8()`(OpenCV Bayer 코드명 오프셋 관례를 docstring에 명시해 고정)로 교체. HTTP 미리보기/촬영 서버 구조(락으로 세션 직렬화)는 유지, 순수 캡처 백엔드만 교체. `--single-shot` 플래그 신규 추가(원격/스크립트 검증용, HTTP 서버 없이 1장 캡처 후 numpy 통계 출력하고 종료).
  - **실제 촬영 검증(pseudo 테스트 아님):** RPi에서 `python3 vision/tools/rpi_capture.py --single-shot`을 실제로 실행해 4608x2592 풀해상도 실사진 획득(파일 `single_shot.png`, shape=(2592,4608,3) uint8, mean≈23.1 std≈25.3 min=16 max=255 — 어두운 실내지만 균일하지 않은 실제 분산).
