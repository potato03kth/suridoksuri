# SITL-7 정적 설계 감사 — `offboard_node.py` VTOL 상태머신

SITL 실행 **전에** 코드만으로 상태머신을 감사한 기록.
목적 ①질문 1("좋은 시퀀스인가")에 코드 근거로 답한다 ②Phase 3 표적 시나리오를 날카롭게 한다
③**22개 시나리오의 결과를 미리 예측**해두고 실측과 대조해 "우리가 코드를 제대로 이해했는가"를 검증한다.

줄번호는 `fc_ros/fc_ros/nodes/offboard_node.py`(1207줄) 기준. 다른 파일은 파일명 명시.

## 0. 세 질문에 대한 정적 답

| 질문 | 정적 판정 |
|---|---|
| **1. 좋은 시퀀스인가** | 상태 **분해**는 타당(VTOL 물리 단계와 1:1). 그러나 전이 조건이 거의 전부 "관측량이 목표값이 되기를 기다림"이고, **12개 상태 중 타임아웃/폴백이 있는 것은 HOLD·OVERRIDE·(경고만 하는)LANDING 3개뿐**. 나머지 9개는 조건이 안 오면 영구 대기. 특히 `TRANSITION_FW`/`TRANSITION_MC`의 탈출은 **`vtol_state` 단일 신호**에만 걸려 있고 신선도 검사가 없다. |
| **2. 흐름이 부드러운가** | 상태 **내부**는 부드럽게 설계됨(yaw 필수 인자화, MC 램프, 정착 판정, OFFBOARD 프라이밍). 반면 **상태 경계는 대부분 무보정 계단**. A1 기준 최소 3곳에서 100ms 안에 300m/170m/**113m** 위치 setpoint 점프. **슬루레이트가 걸린 경로는 MC 분기(`_mc_pos_ramp`) 하나뿐이고 VTOL 경로엔 전무.** |
| **3. 예상대로 작동하는가** | 직선 단일 레그(A1/A2/B1/B6)는 SITL-4 재현이 유력. **다중 WP·폐곡선·단거리는 코드만으로도 실패가 예측된다** — 원인은 하나로 수렴한다: `TRANSITION_FW`/`FOLLOWING` 종료판정/`HOLD`가 전부 **`_pts[-1]`(경로 최종점)** 을 절대 목표로 쓰는데, 이것이 "진행 방향"과 무관한 좌표이기 때문. |

## B. setpoint 연속성 — 경계별 점프 (A1: `[0,0,50]→[300,0,50]`, `transition_alt=50`, 10Hz)

| 경계 | 점프 |
|---|---|
| CLIMBING→TRANSITION_FW | 0 (CLIMBING은 한 틱도 발행 안 함, 첫 setpoint가 P1의 속도 0) |
| P1→P2 | 위치 0. **yaw_rate 0 → 최대 ±0.5rad/s 계단** (A1은 무해, B8에서 즉시 발현) |
| **P2→P3** | **채널이 바뀐다**(속도→위치) + 위치 **300m 계단**. 암묵속도 3000m/s → PX4 MC 위치제어 포화. **전 구간 최대 불연속** |
| P3→P3'(ACTIVE) | 0 (설계대로 연속) |
| **P3'→STREAMING** | along-track **−170m**(`_pts[-1]` → lookahead). 직선은 궤적 영향 없음. **곡선/L자에선 lateral 스냅백이 지배적** |
| STREAMING→FOLLOWING | 위치 0(같은 식). **yaw만 실측헤딩→lookahead 방향 계단** |
| FOLLOWING→TRANSITION_MC | +60m 전방 계단 — 이건 "끝점 급선회 방지"의 **의도된 개선** |
| **TRANSITION_MC→HOLD** | **113m 역방향 계단**(pos≈343, 오버슈트 43m 기준 → `_pts[-1]`=300). dt=0.1s → 암묵 1130m/s. `_step_hold`(986-988) 슬루레이트 없음 — **기존 알려짐** |
| HOLD→LANDING | 스트림 절단(의도) |

**추가:** `transition_alt ≠ waypoints[-1].z`이면 P2→P3 시점에 **고도 계단**도 함께 발생.
C1(20m)에서 **+30m 급상승**, C1(120m)에서 **−70m 급강하** 명령. A1은 두 값이 같아 지금까지 가려져 있었다.

## E. 잘 설계된 부분 (인정)

1. **조종사 인계 최우선 선점 + 영구 스트림 절단**(479-483, 839-852). "되찾아오지 않는다"는 결정과 복귀 경로 명시가 정확.
2. **OFFBOARD 재요청 1Hz throttle**(862-866). 판정 입력이 1Hz 소스라는 사실에서 도출된 값이고, `COM_OF_LOSS_T`와 **독립 축**이라 부작용 없음(setpoint 스트림은 계속 10Hz).
3. **`_publish_pos_setpoint`의 `yaw_ned` 필수 인자화**(814-826). 2026-07-21 yaw 스핀 사고 계열을 **타입 레벨에서** 봉쇄.
4. **`home_amsl` 3중 방어**(신선도→NaN→수렴). 각 방어에 실측 사고 근거가 붙어 있음.
5. **경로 원점 평행이동을 이륙 순간 한 번만 적용하고 L1Guidance 재생성**(635-669) — 지점마다 오프셋을 더하는 방식보다 누락 위험 없음.
6. **OVERRIDE 독립 상태 승격 + AUTO.LOITER 폴백**(888-937). SITL-4 폭주 사고에 대한 정확한 구조적 대응.
7. **CLIMBING의 vz 게이트** — 위치 단독 판정의 스침 통과를 막고, 기본값을 "조건 없음"과 동일하게 둔 회귀안전 규약(`mc_wp_advance`도 동일).
8. **TRANSITION_FW의 20틱 OFFBOARD 프라이밍**(729-746) — PX4의 "요청 전 스트림 선행" 요구를 정확히 만족.
9. **LANDING/DONE/OVERRIDE/PILOT_TAKEOVER의 스트림 절단**(557-560, 846, 912-915) — "velocity-0이 OFFBOARD를 살려둬 FW 폭주"라는 실측을 일반 원칙으로 승격.
10. **TRANSITION_MC의 70m 전방 목표 발상 자체**(948-951) — "끝점 근접 목표 → FW 급선회"를 정확히 해결. 문제는 발상이 아니라 **타임아웃 부재**(E-1).
11. **판정 로직의 순수함수 분리**(`state_logic.py`) — rclpy 없이 테스트 가능, 각 함수에 사고 근거·부호 규약이 주석으로 고정됨.
