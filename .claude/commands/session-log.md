# 세션 종료 절차

이번 세션이 **실제로 건드린 것만** 갱신한다. 안 건드린 트랙·문서는 손대지 않는다.

`$ARGUMENTS` 가 `축약` 이면 3단계(서술 로그)를 **완료·결정·다음 세션 3절로만** 압축하고,
4단계(아카이브)는 건너뛴다. 1·2단계는 축약해도 **반드시** 한다.

---

## 0. 먼저 — 이번 세션의 범위를 확정한다

```bash
git log --oneline <세션 시작 시점>..HEAD
git status --short
```

커밋이 없고 문서 변경도 없으면 여기서 끝낸다(기록할 게 없다). 미커밋 변경이 남아 있으면
**먼저 커밋한다** — 커밋 태그는 `[main]`/`[mc-hw]`/`[sitl]`/`[vtol-hw]`/`[vision]`.

---

## 1. 트랙 보드 갱신 (생략 금지)

| 도메인 | 문서 | 갱신할 곳 |
|---|---|---|
| FC (`[main]`/`[mc-hw]`/`[sitl]`/`[vtol-hw]`) | `docs/session_status.md` | 건드린 트랙 블록의 `**마지막:**` |
| vision (`[vision]`) | `docs/vision_status.md` | 해당 트랙 블록 |

- 기존 `**마지막:**` 항목은 **`그 전 (날짜, 요약)` 으로 강등**하고 새 항목을 위에 넣는다.
- 트랙 헤더 한 줄(`### 🎯 ... — ▶ 활성 (...)`)도 상태가 바뀌었으면 같이 고친다.
- **프런트매터 `last_updated` 를 오늘 날짜로.**
- 🔴 **낡은 값 사냥.** 이번 세션이 파라미터·기본값·경로를 바꿨다면 트랙 보드 본문에 **옛 값이
  서술로 남아 있는지 `grep` 한다.** (2026-07-29 에 `transition_alt` 50→25 · 경로 300→150 m ·
  타임아웃 120→180 s 가 바뀌었는데 보드에 옛 값이 남아 다음 세션이 오독할 뻔했다.)

## 2. handoff 갱신 — **오케스트레이션 세션이면 이게 1단계보다 중요하다**

서브에이전트를 띄웠거나 사용자가 "너는 오케스트레이터이다"로 시작한 세션이면 **반드시** 한다.

| 문서 | 언제 |
|---|---|
| `docs/fc_orchestration_handoff_*.md` | FC 오케스트레이션 |
| `docs/vision_orchestration_handoff.md` | vision 오케스트레이션 |
| `docs/fc_precision_land_handoff.md` | F2 를 건드렸으면 |
| `docs/field_vision_landing_*.md` | 현장 절차가 바뀌었으면 |

**커밋 메시지에 원리적으로 안 담기는 것을 여기에 쓴다** — 커밋은 "한 것"의 기록이다:

1. **사용자 결정 대기 항목** (해소된 것은 취소선 + 근거, 새로 생긴 것은 추가)
2. **이 세션의 목적** — 왜 시작했는지. 사용자 지시 원문이 있으면 그대로
3. **미실시·보류와 그 사유**
4. **함정** — 다음 사람이 같은 데 빠질 것
5. **우선순위가 바뀌었으면 그 사실을 맨 위에** — 아래 절들이 낡은 순서를 말하고 있을 수 있다

> 🔴 **프런트매터 `status` 가 본문과 어긋나지 않는지 확인.** 본문 §4 가 "전부 종료"인데
> 헤더가 "3개 실행 중"으로 남아 있던 사고가 있었다(2026-07-28→31).

## 3. 서술 로그 기록 — `docs/session_log.md`

**최신이 위**다. 파일 맨 위 `---` 구분선 바로 아래에 삽입한다.

```markdown
## YYYY-MM-DD — [태그] 한 줄 제목

**브랜치:** `브랜치명` · **커밋:** `해시`·`해시`
**목적:** 왜 이 세션을 시작했는지 (사용자 지시가 있었으면 그대로)

### 완료
- 항목마다 **근거 수치·파일·커밋**을 함께

### 발견
- 예상과 달랐던 것. 🔴 를 붙일 것: 다음 세션이 모르면 사고 나는 것

### 결정
- 사용자 결정은 **"(사용자)"** 를 명시. 되돌리지 말라는 것은 그렇게 적는다

### 다음 세션
1. 우선순위 순

### 주의
> 미검증인데 검증된 것처럼 읽힐 수 있는 것. "구현 완료"를 "동작 확인됨"으로
> 오독하게 두지 말 것
```

`축약` 이면 **완료·결정·다음 세션** 3절만 쓴다.

## 4. 아카이브 (`축약` 이면 생략)

`docs/session_log.md` 는 **최근 8개 세션만** 유지한다. 초과분은 오래된 것부터
`docs/archive/session_log_YYYY-MM.md` 의 **맨 위**로 옮긴다(거기서도 최신이 위).
`session_log.md` 헤더의 "과거 기록:" 줄에 기간을 갱신한다.

---

## 5. 커밋 + push

```bash
git add -A docs/ && git commit && git push origin HEAD:dev--vision-computing-module
```

- 워크트리에서 작업 중이면 **`git checkout -B <공유브랜치>` 금지** — 커밋이 고아가 된 사고가 있었다.
  `git fetch` → `git rebase origin/dev--vision-computing-module` → **refspec push**.
- 공용 stash 스택을 쓰지 말 것(다른 세션과 공유된다).

## 6. 마지막 — 세션을 실제로 닫는다

**이 절차를 실행했다고 세션이 닫히는 게 아니다.** 워크트리가 잠긴 채 프로세스가 살아 있으면
다음 세션이 그것을 "진행 중"으로 본다.

```bash
git worktree list --porcelain | awk '/^worktree /{w=$2} /^locked/{print w}'
```

작업이 끝났으면 세션을 **종료**하고(`ExitWorktree` 또는 세션 종료), 유령 잠금은
`git worktree unlock <경로>` → `git worktree remove <경로>` 로 정리한다.

> **이 절차가 빠지면 아무도 모른다.** `session_log.md` 는 진입 경로가 아니라 종료 산출물이라
> 며칠 비어 있어도 다음 세션이 불편해하지 않는다 — 2026-07-28~30 에 74커밋이 그렇게 누락됐다.
> 조용히 썩으므로 **매번 실행하는 것 말고 방어책이 없다.**
