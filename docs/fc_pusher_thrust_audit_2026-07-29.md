# 푸셔모터 결선·추력 방향 로그 감사 (2026-07-29)

**질문:** 푸셔모터의 결선 방향이 뒤집혀 있어 추력이 후방으로 나가는 것 아닌가?
(flight06 에서 "정북을 입력했는데 남쪽으로 갔다" 는 관찰이 계기)

**답:** **아니다. 결선 방향은 옳다.** 실제 문제는 방향이 아니라 **푸셔가 아예 구동되지
않는 것**이다. 2026-07-25 까지는 정상적으로 **전방** 추력을 냈고, 2026-07-28 부터
전류를 전혀 끌지 않는다.

물리 점검은 방향(3상 순서)이 아니라 **전원·상(phase) 도통**부터 봐야 한다. §6.

## 1. 측정 방법 — 왜 body-x 가속도가 추력 부호를 그대로 드러내는가

가속도계는 **비력(specific force)** 을 잰다. 동체좌표 x축 성분은

```
f_bx = (F_푸셔 + F_공력x) / m
```

리프트 로터 4기는 `CA_ROTOR0..3_AZ = -1.0` 으로 **동체 −z 방향 힘만** 낸다 →
**body-x 에 기여가 0**. 즉 `vehicle_acceleration.xyz[0]` 은 자세와 무관하게
푸셔 추력 + 공력항력만 담는다. 기체를 어떻게 기울여도 이 관계는 깨지지 않는다.

검증: `vehicle_acceleration.xyz[2]` 호버 평균 = **−9.65 m/s²** → 중력반력 포함 비력이
맞다(중력보상값이면 0 이어야 함). 부호 규약 확인 완료.

전류는 `battery_status.current_a` 총전류만 있다 — `DSHOT_TEL_CFG=0`, `esc_status`
토픽 부재로 **ESC 개별 전류·RPM 텔레메트리는 없다**. 다만 킬스위치 구간에서
0.00 A 를 읽으므로(§5) 전류계 자체는 정상 동작한다.

## 2. 신호 경로 — FC 가 내보낸 명령은 완벽히 정상이다

| 항목 | 값 | 판정 |
|---|---|---|
| `CA_ROTOR4_AX / AY / AZ` | **+1.0** / 0 / 0 | 푸셔 = 동체 **+X(전방)** 추력축 |
| `CA_ROTOR4_PX / PY / PZ` | 0 / 0 / 0 | 중심 배치 = 토크 기여 없음 |
| `PWM_AUX_FUNC5` | 105 (Motor5) | 푸셔 = **AUX 5번 출력** |
| `PWM_AUX_MIN5 / MAX5 / DIS5` | 1100 / 1900 / 1000 | 표준 |
| `PWM_AUX_REV` | **0** | **출력 반전 없음** |
| `PWM_MAIN_REV` | 6 (=ch2,3) | 서보 전용 — 모터와 무관 |
| `VT_F_TRANS_THR` | 1.0 | 천이 시 푸셔 100% |

flight06 실측 지령·출력 (`actuator_motors.control[4]` → `actuator_outputs#1.output[4]`):

```
t=26.17  m4=0.191  AUX5=1252.6 us      (1100 + 0.191*800 = 1252.8  ✓ 매핑 정확)
t=27.07  m4=1.000  AUX5=1900.0 us
  ...    m4=1.000  AUX5=1900.0 us      약 5.5 초 연속 유지

```

→ **ESC 는 1900 µs(전진 최대)를 정확히, 충분히 오래 받았다.**

## 4. flight06 의 남쪽 이탈은 푸셔가 원인이 아니다

이 기체는 **상시 기수하향 호버 트림**을 갖는다. 정지호버(|v|<0.5, AGL>5m) 구간 평균:

| 로그 | 호버 피치 | 실측 ax | 9.81·sin(pitch) |
|---|---|---|---|
| 07-25 flight14 | −6.52° | −1.07 | −1.11 |
| 07-25 flight17 | −5.98° | −1.05 | −1.02 |
| 07-28 flight02 | −4.27° | −0.77 | −0.73 |
| 07-29 manual_231 | −3.93° | −0.66 | −0.67 |
| 07-29 manual_239 | −4.23° | −0.74 | −0.72 |
| **07-29 flight06** | **−5.10°** | **−0.85** | **−0.87** |

세 날짜 전부 −4 ~ −6.5° 이고 `ax ≈ 9.81·sin(pitch)` 가 매번 일치한다
→ 그날 바람이 아니라 **기체 고유 트림**(CG 전방 편중 또는 IMU 장착 피치 오차).

flight06 에서 천이가 시작되면 `VT_PITCH_MIN=0` 이 걸려 피치 지령이 0 이 된다.
−5.1° 의 기수하향이 풀리면서, 그것과 균형을 이루던 **약 0.9 m/s² 의 후방력이 그대로
남는다.** 실측 후진 가속 **−0.42 m/s²** 가 여기서 나온다.

검산: `a_전방 = ax − 9.81·sin(pitch) = −0.63 − 9.81·sin(−1.3°) = −0.41 m/s²`.
GPS/EKF 속도 미분값 **−0.42 m/s²** 와 일치 → 물리 폐합.

**같은 −5.98° 트림을 갖고도 07-25 flight17 은 전진했다.** 살아있는 푸셔가
+2.5 m/s² 를 내어 1.0 m/s² 의 트림 후방력을 압도했기 때문이다.
차이는 오직 푸셔의 생사 하나다.

송신기 스위치 재확인 가치가 있다.

## 6. 고장 구간 특정과 물리 점검 순서

```
2026-07-25 11:22  flight17     푸셔 정상 (+15.9 A, ax +1.9)   ← 마지막 정상
        │
        │   ※ 이 사이에 2026-07-28 PX4 재플래시 (logs/2026-07-28_px4_flash)
        │      → 그러나 파라미터 diff 결과 푸셔 관련 파라미터 전부 무변경.
        │        CA_ROTOR4_*, PWM_AUX_FUNC5/MIN5/MAX5/DIS5, PWM_AUX_TIM*,
        │        VT_F_TRANS_THR 동일. 바뀐 39 개는 가속도계·자이로·자기계
        │        캘리브레이션, CAL_BARO0_OFF, COM_FLIGHT_UUID, RC 스위치 매핑뿐.
        │      → 펌웨어·설정 원인 아님. AUX5 핀 **이후**의 물리 경로 문제.
        ▼
2026-07-28 10:29  flight02     푸셔 무추력 (−0.3 A)           ← 최초 이상
2026-07-29 11:24  flight06     푸셔 무추력 (+0.7 A)
```

**점검 우선순위 — "방향"이 아니라 "도통"부터다.**

1. **푸셔 ESC 전원 입력**(배터리/PDB → ESC 굵은 선, XT 커넥터). 07-28 의 `−0.3 A`(=증가 0) 는
   ESC 가 전원 자체를 못 받는 것과 가장 잘 맞는다.
2. **ESC → 모터 3상 중 1상 단선/접촉불량**(불릿 커넥터, 납땜부, 피복 내 단선).
   한 상이 열리면 센서리스 ESC 는 기동에 실패해 **소리만 나고 안 돌며 소전류만 흐른다**
   — flight06 의 `+0.7 A` 와 부합. **"회전 방향이 이상해 보인다"는 인상의 흔한 원인**이므로
   이번 의문의 실체가 여기일 가능성이 높다.
3. **AUX5 시그널선 / GND**(FC 커넥터 이탈, 접지 공통 여부).
4. **ESC 소손** (FET 손상, 기동 실패).
5. **프로펠러 어댑터 슬립** — 이 경우만 소전류 상승 + 무추력이 함께 나온다.

**방향 확인은 그 다음이다.** 전류가 정상 대역(스로틀 100% 에서 총전류 +10 A 이상)으로
돌아온 뒤에 봐야 의미가 있다. 그 시점에도 방향이 반대라면 3상 중 **임의의 두 상을
맞바꾸면** 뒤집힌다 — 다만 §3 에 따라 **원래 결선은 옳았으므로 바꾸지 말 것.**

**지상 재현 절차:** 프로펠러 제거 후 기체 고정 → arm → `VT_FWD_THRUST_EN` 을 건드리지
말고 천이 스위치로 푸셔만 스풀업 → `battery_status.current_a` 관찰.
정상이면 프로펠러 없이도 무부하 전류 수 A 가 뜬다. 0 A 면 §6-1/2/3 확정.

## 7. 재현 명령

```bash
python3 - <<'PY'
import numpy as np
from pyulog import ULog
u = ULog('logs/2026-07-29_flight06/log_248_2026-07-29-11-24-04.ulg')
t0 = u.start_timestamp
g = lambda n, m=0: next(d for d in u.data_list if d.name == n and d.multi_id == m)
ts = lambda d: (d.data['timestamp'] - t0) / 1e6
am, ao, bt, va = g('actuator_motors'), g('actuator_outputs', 1), g('battery_status'), g('vehicle_acceleration')
m4 = np.array(am.data['control[4]'])
on = ~np.isnan(m4) & (m4 > 0.9)
lo, hi = ts(am)[on][0], ts(am)[on][-1]
c, tb = np.array(bt.data['current_a']), ts(bt)
ax, tv = np.array(va.data['xyz[0]']), ts(va)
pre = (tb > lo - 8) & (tb < lo - 0.5) & (c > 0.5)
dur = (tb > lo + 0.5) & (tb < hi) & (c > 0.5)
print('pusher full  t=%.2f..%.2f' % (lo, hi))
print('current  off=%.2f A  on=%.2f A  delta=%+.2f A' % (c[pre].mean(), c[dur].mean(), c[dur].mean() - c[pre].mean()))
print('body ax  off=%+.2f   on=%+.2f' % (ax[(tv > lo - 8) & (tv < lo - 0.5)].mean(), ax[(tv > lo + 0.5) & (tv < hi)].mean()))
PY
```
