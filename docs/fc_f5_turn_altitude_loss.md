## 0. 요약 — 세 질문에 대한 답

**A. 우리 코드에 선회↔고도 연결점이 있는가 → 🟢 없다.**
`offboard_node.py` · `state_logic.py` · `l1_guidance.py` 전체에서 `state.roll` / `curvature` /
`kappa` 참조가 **0건**이다. FW 구간 고도 지령은 `_fw_alt()` 하나로 수렴하고, 그것은
`fw_setpoint_alt(alt_ramp, cruise_alt, vehicle_alt, max_step)` — **뱅크·곡률·roll rate 를
인자로 받지 않는다.** 수렴 후에는 `_cruise_alt` 상수를 그대로 낸다.

**B. PX4 TECS 가 뱅크를 보상하는가 → 🟢 절반만. 스로틀은 보상, 피치는 무보상.**
`TECS.cpp:569-570` 이 `ste_rate.setpoint += load_factor_correction * (load_factor - 1)` 로
**총에너지율 요구**에 뱅크 항을 더한다(`load_factor = 1/cos φ`, 게인 = `FW_T_RLL2THR`).
그런데 이 항이 쓰이는 곳은 `_calcThrottleControlSteRate()` **하나뿐**이다.
피치를 만드는 `_calcPitchControlSebRate()`(`TECS.cpp:427-448`)는 `param.load_factor` 를
**참조하지 않는다.** 즉 **"뱅크를 걸었으니 받음각을 올려라"는 경로가 PX4 에도 없다.**

**C. 얼마가 불가피한가 → 🟢 거의 전부가 제어 결함이다.**
최악 사례 B4(U턴 135°)에서 코너 침하 6.63 m 중 **총에너지 손실은 0.91 m(14%)**,
나머지 **5.72 m(86%)는 고도→속도 교환**이다. 스로틀은 전 구간 포화하지 않았다
(첨두 0.352 / `FW_THR_MAX`=0.6, 즉 여유 41%). 물리적으로 불가피한 몫은
**≤1 m** 로 추정된다(§5.3).

🟢 FW 위치 setpoint 를 내는 자리는 넷이고 **고도 성분은 전부 `_fw_alt()` 하나**다.

| 자리 | 파일:줄 | 고도 인자 |

| `STREAMING`(FW) | `fc_ros/fc_ros/nodes/offboard_node.py:860` | `self._fw_alt(state)` |

`_fw_alt()`(`:1316-1354`)는 `fw_setpoint_alt()`(`fc_bridge/execution/state_logic.py:551-585`)

FOLLOWING 전 구간에서 **50.455 m 로 완전 상수**였다(min=max=mean).
→ 램프는 F-5 를 좋게도 나쁘게도 만들지 않는다. **F-5 는 램프 도입 전후로 동일하다.**
(⚠️ 램프 도입 후 선회 경로 SITL 런은 **아직 없다** — `logs/2026-07-29_r5_f9/` 는 전부

**우리가 PX4 에 주는 것은 결국 이것뿐이다** (🟢 `FixedWingModeManager.cpp:2123-2196`):
`trajectory_setpoint.position[0..2]` → `lat/lon/alt`. `cruising_speed = NAN; // ignored` 로
**하드코딩**돼 있어 **오프보드에서 목표 대기속도를 지정할 수단이 없다**(§8-③ 에서 중요).

## 3. B — PX4: TECS 의 뱅크 보상은 스로틀 전용이다

### 3.1 존재하는 보상 (파일:줄)

| 위치 | 코드 | 대상 |
|---|---|---|
| `src/lib/tecs/TECS.cpp:569-570` | `ste_rate.setpoint += param.load_factor_correction * (param.load_factor - 1.f);` | **총에너지율 → 스로틀** |
| `src/lib/tecs/TECS.hpp:651` | `set_roll_throttle_compensation(...)` ← `FW_T_RLL2THR` | 〃 게인 |
| `.../FwLateralLongitudinalControl.cpp:614-621` | `_load_factor_from_bank_angle = 1/max(cos φ, ε)` → `set_load_factor()` / `set_equivalent_airspeed_min()` | 〃 + **최소속도 상향** |
| `src/modules/fw_att_control/FixedwingAttitudeControl.cpp:275-287` | `pitchrate_ff = q1*yawrate_ff/(...)`, `yawrate_ff = g*q1/V` | **선회 협조(kinematic)** — 자세 *오차*에 더하는 **각속도** FF. 양력 부족 보상이 아니다 |

### 3.2 없는 보상 — 여기가 결함의 위치다

🟢 `TECSControl::_calcPitchControlSebRate()` (`TECS.cpp:427-448`) 전문에 `load_factor` 가
**등장하지 않는다.** 피치 지령은
`seb_rate.setpoint = spe_rate.setpoint*w_spe − ske_rate.setpoint*w_ske` 뿐이고,
`spe_rate.setpoint = height_rate_setpoint * g`,
`height_rate_setpoint = (alt_sp − alt) / FW_T_ALT_TC`
(`TECS.cpp:331-339`, `TECS.hpp:635` 에서 `altitude_error_gain = 1/FW_T_ALT_TC`).

> **즉 PX4 의 고도 유지 루프는 "고도가 이미 떨어진 뒤에야" 반응한다.**
> 뱅크가 걸린 순간 필요한 것은 받음각 증가인데, 그것을 지시하는 항이 어디에도 없다.
> `FW_T_ALT_TC=5.0 s` 라 반응은 시정수 5 초짜리 1차 지연이다.

### 3.3 스로틀 보상은 **실제로 작동했다** (계산 대 실측 일치)

🟢 SITL B4 코너에서 스로틀이 0.26 → **0.352** 로 올랐다. 이론값:

```
STE_rate_max = FW_T_CLMB_MAX·g = 8.0·9.81 = 78.5      (TECS.cpp:298-303)
STE_rate_min = −FW_T_SINK_MIN·g = −2.2·9.81 = −21.6
STE_rate→throttle 환산 = 1/(78.5+21.6) = 1/100.1
Δthr = FW_T_RLL2THR·(1/cos50° − 1)/100.1 = 15·0.5557/100.1 = +0.083
```
실측 상승분 **+0.09**. → **뱅크 보상이 동작하지 않은 것이 아니다.** 다만 그것은
"에너지를 더 넣어라"일 뿐 "그 에너지를 고도로 써라"가 아니다.

원인은 두 겹이다:

### 5.3 물리적으로 불가피한 몫 (🟡 추론)

**정상상태에서는 0 이다.** 뱅크 φ 의 정상 선회를 고도 유지로 돌려면 유도항력이
`n² = (1/cosφ)²` 배로 늘어 추력이 더 필요한데 — 🟢 스로틀 여유가 SITL 41%,
실기체 40%(트림 0.6 → 상한 1.0) 남아 있다. 실속 마진도 충분하다
(🟢 `FW_AIRSPD_STALL`=7, 15 m/s 에서 `n_max = (15/7)² = 4.6`, 필요치 1.74).

**불가피한 것은 과도뿐이다.** 롤이 서는 동안 양력을 즉시 키울 수 없다 —
받음각/피치 내부루프의 지연 τ 만큼 수직력이 모자란다. 램프 φ̇ 로 φ_f 까지 세울 때

```
v_sink_peak ≈ g·τ·ln(sec φ_f)
Δh_불가피   ≈ v_sink_peak · (T_ramp/2 + τ)
```

🟢 내부 피치 루프는 **빠르다** — B4 에서 `pitch_sp` 6.99° 일 때 실제 pitch 8.21°(실제가
지령을 앞선다), 지연 < 0.25 s. τ = 0.2~0.3 s 로 두면 φ_f = 55°, T_ramp = 0.9 s 에서
**Δh_불가피 = 0.7~1.1 m**. φ = 23° 면 **0.1 m 미만**.

> 즉 **6.63 m 중 물리는 1 m 미만이고 나머지는 전부 루프 설계의 결과다.**

### 5.4 용량-반응 모델 (🟡)

코너 이벤트 7 건을 `|Δh| = k·(1 − cos φ)` 로 맞췄다(원점 통과, 물리적 형태:
자유낙하 결손 × 유효 반응시간²).

| 이벤트 | φ | 1−cos φ | \|Δh\| | k |
|---|---|---|---|---|
| B3 | 33.8° | 0.169 | 3.86 | 22.8 |
| B5-1 | 33.5° | 0.166 | 4.11 | 24.7 |
| A3 | 33.9° | 0.170 | 4.54 | 26.7 |
| B5-3 | 40.5° | 0.240 | 7.21 | 30.1 |
| B5-2 | 40.2° | 0.236 | 7.33 | 31.0 |
| C2 | 53.3° | 0.402 | 6.88 | 17.1 |
| B4 | 55.0° | 0.426 | 6.63 | 15.5 |

- 전체: **k = 24.0 ± 6.0 m** (= ½·g·T_eff², **T_eff = 2.20 ± 0.28 s** — TECS 고도루프의
  유효 반응시간. `FW_T_ALT_TC`=5 s 와 정합적이다)
- **φ ≤ 41° 구간만: k = 27.1 ± 3.4 m** (고뱅크에서 k 가 떨어지는 것은 침하가
  포화하기 때문 — 오차가 커질수록 TECS 요구도 커진다)
- ⚠️ **관측 구간은 전부 φ ≥ 33.5° 다.** 아래(15~27°)로의 외삽은 **미검증**이다.
  다만 직선 비행(φ < 10°)에서 침하 0.9~1.2 m 라는 독립 앵커가 있어 원점 근방은 맞는다.
- ⚠️ 이 모델은 **계단형 뱅크 진입**(실측 12~62°/s)에서 얻은 것이다. 클로소이드로
  완만히 눕는 진입은 TECS 에 시간을 주므로 **모델보다 덜 침하한다** → 아래 예측은 **상한**이다.

**지속시간은 변수가 아니다.** 🟢 B5 는 30° 이상 체류 5.8 s 에 6.82 m,
B4 는 3.5 s 에 7.45 m — 더 오래 돈다고 더 가라앉지 않는다.
**침하는 코너 진입 과도이지 누적이 아니다.** (다만 폐곡선은 코너마다 반복된다.)

> 통제된 효과가 아니다.)

### 6.2 신 플래너(`planner_g2_redesign` 2단계) 도입 후 — **여기서는 유의미하다** (🟡)

신 플래너는 `|κ|max ≈ 1.4 × κmax` 를 달성한다(🔵 `docs/planner_g2_redesign.md` §0).
그러면 비행 뱅크가 처음으로 `a_max_g` 에 의해 결정된다.

⚠️ **단, 기체는 `v_cruise` 로 날지 않는다.** 🟢 오프보드에서 `cruising_speed` 가
하드코딩 NaN 이라 PX4 는 항상 `FW_AIRSPD_TRIM = 15 m/s` 로 난다(실측 TAS 평균 14.7 m/s).
플래너는 `v_cruise = 18` 로 곡률을 정하는데 기체는 15 로 난다 → 실제 횡가속은
`(15/18)² = 0.694` 배가 된다. `docs/planner_g2_redesign.md` §6(C) 표는 18 m/s 가정이므로
그대로 쓰면 안 된다.

```
a_lat(실제) = v_act² · κ = 1.4 · a_max_g · g · (15/18)² = 0.972 · a_max_g · g
φ = atan(a_lat/g)
침하_선회 = k · (1 − cos φ),  k = 27.1 ± 3.4 m   (§5.4)
총 하방 편차 = 침하_선회 + 기저 0.9~1.2 m       (§1)
```

| `a_max_g` | 실제 횡가속 | **실제 뱅크** | 선회 침하 | **총 하방 편차** | 기준 ±3 m |
|---|---|---|---|---|---|
| **0.30** | 0.29 g | **16.3°** | 1.09 m [0.95–1.23] | **2.0 ~ 2.3 m** | ✅ 통과 |
| **0.43** | 0.42 g | **22.7°** | 2.10 m [1.83–2.36] | **3.0 ~ 3.3 m** | ⚠️ **경계·초과 가능** |
| **0.50** | 0.49 g | **25.9°** | 2.72 m [2.37–3.07] | **3.6 ~ 3.9 m** | ❌ **초과** |

**역산 — 지금 제어로 ±3 m 를 지키는 상한:**
`침하_선회 ≤ 3 − 1.1 = 1.9 m` → `1 − cos φ ≤ 0.070` → **φ ≤ 21.6°** → **`a_max_g ≤ 0.41`**.

> 🔴 **결론:** `a_max_g` 상향은 **지금은 안전하고**(§6.1), **신 플래너가 들어온 뒤에는
> 0.41 이 손익분기**다. **0.43 은 경계 위, 0.50 은 명백히 초과**다.
> **그러나 §8-① 의 TECS 튜닝을 먼저 하면 이 한계가 통째로 올라간다** —
> 침하가 2~3 배 줄면 0.50 이 1.2~1.6 m 로 내려온다.
> **순서를 뒤집지 마라: TECS 먼저, `a_max_g` 나중.**

⚠️ 이 표는 **SITL 기반 외삽**이다. 실기체 FW+OFFBOARD 비행 실적은 여전히 **0 건**이고,
`NPFG_PERIOD` 가 실기체에서 10(SITL 12)이라 뱅크 진입이 더 빠를 수 있다(§3.4).

    (다만 지금은 "고도가 떨어진 뒤"라 T_eff ≈ 2.2 s 만큼 앞당겨진다).
  - ⚠️ 구현 시 주의: **F-9 램프 *뒤에* 더해야** 램프의 수렴 판정(`slew_setpoint` 규약)을
    깨지 않는다. 그리고 선회 종료 시 상방 오버슈트가 생길 수 있다(현재도 +1.5~2.7 m 있음).

- **②-b 계획 곡률 기반 (선행 예측)** — lookahead 지점의 계획 κ 로 `φ_pred = atan(v²κ/g)`.
  **현 플래너로는 불가능하다** — 계획 곡률과 실제 뱅크가 2.4~4.8 배 어긋난다(§4.1).
  **신 플래너 도입 후에만 성립**한다.

### ③ 선회 시 속도/뱅크 조정 — 소관: **플래너 + PX4 파라미터**

- 🔴 **"코너에서 감속"은 현재 인터페이스로 불가능하다.**
  🟢 `FixedWingModeManager.cpp:2131` 이 `_pos_sp_triplet.current.cruising_speed = NAN; // ignored`
  로 하드코딩돼 있어 오프보드에서 목표 대기속도를 줄 방법이 없다. 기체는 항상
  `FW_AIRSPD_TRIM`(15)으로 난다.
  → **`docs/planner_g2_redesign.md` §6(A) "코너에서 감속" 은 플래너가 `v_ref` 를 내도
  하류에서 소비되지 않는다.** (F-13 "속도 프로파일 전량 미사용"과 같은 뿌리다.)
  우회로는 `FW_AIRSPD_TRIM` 자체를 낮추는 것(전 구간 영향)뿐이고, 비행 중 `param_set` 은
  🔵 캠페인에서 "주입 경로 미검증"으로 남아 있다.
- **`FW_R_LIM` 50 → 30** — 모델상 침하 첨두 8.5 m → 3.2 m. 대신 선회반경이
  15 m/s 에서 19.2 m → 39.7 m 로 늘어 **코너를 더 크게 벗어난다**(지오펜스·WP 통과 요건 직결).
- **근본: 코너 불연속 제거** — lookahead 목표점이 한 틱에 50.5 m 튀지 않게 한다.
  ⓐ 신 플래너(`planner_g2_redesign` 2단계)로 WP 꺾임을 없애거나
  ⓑ `target_point_ned()` 출력에 슬루레이트를 걸거나(F-6 의 `_step_hold` 권고와 같은 처방)
  ⓒ `_FW_LOOKAHEAD`(70 m)를 코너 근방에서 줄인다.
  → **F-5 와 F-6 은 코너에서 같은 사건이므로 한 번에 고쳐진다.**

### 🎯 권고 (1개)

> **①의 `FW_T_SPDWEIGHT` 인하(1.0 → 0.5)를 1순위로 SITL 검증하라.**
> `B4`(U턴 135°)·`B5`(폐곡선)·`B3`(직각) 3 시나리오면 충분하다. 같은 런에서

**근거:** ⓐ 침하의 76~86% 가 총에너지 손실이 아니라 **고도↔속도 배분 오류**이고,
`FW_T_SPDWEIGHT` 가 TECS 안에서 **그 배분을 정하는 단 하나의 파라미터**다.
ⓑ 코드 변경 0, 롤백 즉시. ⓒ 부작용 방향이 예측 가능하다 — 스로틀 여유 41%,

**그 다음:** ③ⓐ/ⓑ(코너 불연속 제거)가 근본치료지만 플래너 2단계와 묶여 일정이 길다.
**②는 ①이 부족할 때의 보완책**으로 남긴다(①과 ②를 동시에 넣으면 어느 쪽이 들었는지 모른다).

   `FW_T_CLMB_MAX`(5 vs 8)·`FW_THR_TRIM`(0.6 vs 0.25) 차이 때문에 실기체 침하량은
   여기 수치와 다를 수 있다.

   실측이 아니다.
3. **뱅크 15~27° 구간의 실측이 없다.** §5.4 모델은 φ ≥ 33.5° 에서 피팅돼 §6.2 예측은
   하향 외삽이다. 산포도 크다(k = 15.5~31.0).
4. **바람은 독립 기여자다.** 🟢 `C4_pxvehicle_wind8`(8 m/s)는 뱅크 첨두 12.4° 인데
   침하 3.99 m, 그중 총에너지 손실 −3.71 m 로 **선회 침하와 성질이 다르다**. 이 문서는
   무풍만 다뤘다.
5. **`C2` 천이 직후 19.6 m 횡이탈의 원인**은 여전히 미규명이다(캠페인 §6 그대로).
   이 문서는 그 뒤의 53° 복귀 선회만 설명했다.
6. **`_calcPitchControlOutput` 의 적분항 기여**를 실측 분리하지 않았다
   (`pitch_integ` 첨두 0.143 rad = 8.2°, 전체 `pitch_sp` 16.5° 의 절반).
   지속 선회에서 이것이 결국 오차를 없애는지는 3.5 초 창에서 확인 불가.
